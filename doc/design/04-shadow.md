# 04. 그림자 조작·표현·상호작용

> 기준: V8.1.0 / main `5ea02af8c748bfc1207a06932154407bbf3a0232`. 이 문서는 현행 구현을 정리합니다. 기획 의도·제작 기준·후속 검토는 별도로 표시합니다.

## 핵심 역할

보라색 상자 그림자는 상자를 움직이는 손잡이이자, 현실의 장치에 닿는 원격 조작 수단이다. 상자는 벽에 막히지만 그림자는 벽과 빈 공간을 가로질러 장치에 닿는다. 그림자 자체는 상자를 지지하는 다리가 아니다.

## 상자·광원·그림자의 관계

상자 중심 B, 광원 위치 L, 그림자 중심 S의 관계는 `S = B + 0.5(B-L) = 1.5B - 0.5L`이다.

예: B=(400,500), L=(200,100)이면 S=(500,700)이다. 광원을 고정하고 상자를 오른쪽으로 100 옮기면 그림자는 150 이동한다. 상자를 고정하고 광원을 오른쪽으로 100 옮기면 그림자는 왼쪽으로 50 이동한다.

이것은 게임용 2D 투영 규칙이다. 실제 광학을 시뮬레이션하거나 벽에 빛이 가려져 그림자가 생성·소멸하는 구현이 아니다. 광원과 상자가 겹치면 빛축 방향을 정할 수 없어 축 이동량은 0이 된다.

## 이동

자유 이동 방에서 그림자 입력 변화량 dS는 상자에 `dB=dS/1.5`로 전달된다. 이전 시제품의 역방향 이동이 아니라 **같은 방향**이다. 축 이동 방에서는 선택한 광원과 상자를 잇는 축에 투영한 성분만 전달한다. 실제 상자의 충돌이 최종 이동을 제한한다.

## 그림자 형태와 접촉

상자 폭 w, 높이 h일 때 그림자는 반경 `(0.61w,0.39h)`인 타원으로 그려진다. 점형 ◇ 장치는 그 중심점이 타원 안에 들어가면 작동한다. 긴 그늘판은 그림자 중심이 판의 직사각형 안에 들어가는지 검사한다. 두 판정을 서로 혼동하지 않는다.

## 둘 이상의 그림자

현재 캠페인은 광원 최대 2개다. 각 광원마다 상자 그림자가 생기며 둘 다 상자와 함께 움직인다. A/B 선택은 어떤 광원의 축을 사용해 조작하는지 정할 뿐, 다른 그림자를 고정하거나 없애지 않는다.

센서는 선택 여부와 관계없이 **모든 상자 그림자 중 하나라도** 닿으면 작동한다. 현재 센서를 'A 전용/B 전용'으로 지정하는 데이터 필드는 없다. 필요한 그림자가 정해지는 문제는 배치상 관계에서 나온다.

## 화면 밖과 선택

계산상의 그림자는 화면 밖에 있을 수 있다. UI는 가장자리 표시를 제공하고 패드로도 조작할 수 있게 한다. 표시 위치를 화면 안에 붙인다고 실제 센서 좌표가 달라지지 않는다.

그림자를 직접 잡기 어려우면 패드를 사용한다. 상자를 선택한 상태에서 상자/발판 그림자가 겹치면 상자 그림자의 선택을 우선하는 처리가 있다.

## 발판 그림자와의 구분

발판 그림자는 발판의 길이를 조절하는 손잡이다. 상자 그림자와 달리 센서 판정에 참여하지 않는다. 실제 발판과 점선으로 연결하고 청록 발판 A/B와 선택 대상을 구분한다. 상세 규칙은 [지형·발판](07-terrain-and-platforms.md)에 정리한다.

## 기획 의도와 검토 기준

9번에서 벽 속 장치를 그림자로 누르며 '상자 대신 그림자가 필요한 이유'를 보여준다. 12번은 타원 형태, 17번은 광원 이동, 29번 이후는 선택하지 않은 그림자까지 고려하게 한다. 그림자 없이 상자를 직접 옮겨도 동일한 문제라면 그림자의 역할이 충분한지 다시 검토한다.
