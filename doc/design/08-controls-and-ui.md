# 08. 입력·화면·힌트·피드백

> 기준: V8.1.0 / main `5ea02af8c748bfc1207a06932154407bbf3a0232`. 이 문서는 현행 구현을 정리합니다. 기획 의도·제작 기준·후속 검토는 별도로 표시합니다.

## 화면 구조

상단에는 게임명/버전, `23+`, 스테이지 선택, 도움말이 있다. 미션 영역은 방 번호·이름·자유/빛축 이동 설명·목표·힌트를 표시한다. 게임판 밖의 조작부에 대상 선택, 패드, 형태/길이, 되돌리기·다시·정밀을 배치한다.

게임판은 1000×1000 월드를 정사각형 캔버스에 맞춘다. 표시 폭은 가용 영역과 최대 620 CSS px에 맞추고, 기기 픽셀비는 최대 3까지 반영한다. 월드 판정은 화면 크기와 분리된다.

## 입력 명세

| 입력 | 상자 선택 | 발판 선택 | 빛 이동 |
|---|---|---|---|
| 게임판 드래그 | 해당 상자 그림자를 잡아 이동 | 그림자 몸체/양끝 손잡이로 길이 변경 | 가동 광원을 잡아 이동 |
| 아래 패드 | 그림자 방향 입력 | 가로는 좌우, 세로는 위아래 길이 | 선택 광원 이동 |
| 방향키 | 자유/선택 축에 따라 이동 | 발판 방향의 성분으로 길이 | 광원 이동 |
| A/D | 가늘게/납작하게 연속 변형 | 짧게/길게 | 변형 없음 |
| 슬라이더/프리셋 | 세로·기본·가로 및 중간값 | 짧게·중간·길게 및 중간값 | 비활성화 |
| Z / R | 되돌리기 / 해당 방 다시 | 동일 | 동일 |

패드의 포인터 이동 이득은 3.2이며 정밀 ON이면 0.4배다. 직접 캔버스 드래그는 화면-월드 비율을 사용한다. 방향키 속도는 일반 400, 정밀 150의 제어 입력 단위/초이고, 실제 상자 이동은 그림자/축 계산을 추가 적용한다. 정밀을 켜도 A/D 변형률까지 같은 비율로 줄어드는 것은 아니다.

## 선택 체계

발판이 없는 방은 그림자/빛 이동 토글과 필요 시 빛 A/B를 표시한다. 발판이 있는 방은 상자·발판 A/B·빛 이동을 구분한다. 다중 광원 선택은 발판이 있는 복합 방에서도 숨기지 않는다. 두 종류의 A/B가 순서 표시로 혼동되지 않도록 캡션을 유지한다.

동시 다중 입력은 처리하지 않는다. 입력 중 다른 포인터/버튼의 충돌을 막고, pointer capture로 판 밖까지 이어지는 드래그를 받는다. 창 비활성화·화면 회전 시 진행 중 조작을 종료한다. 슬라이더에 포커스가 있으면 전역 방향키보다 슬라이더 입력이 우선한다.

## 힌트와 진행 선택

`?`는 전체 규칙과 현재 방 `hint`를 연다. `힌트`는 같은 창의 해당 설명으로 이동한다. 현재 힌트는 방별 하나이며, 30초 정체 감지·3단계 힌트·자동 정답 시연은 없다.

선택 화면은 실제 지형을 그린 썸네일, 번호, 이름, tag, 완료 체크를 제공한다. 모든 방이 열려 있고 `?stage=1..40` 직접 진입을 지원한다. `23+`는 코드상 최초 다중 광원 방을 찾아 이동한다. 별·점수·잠금 해제 보상은 표시하지 않는다.

## 피드백 문구

- 장치가 켜짐: 누른 주체와 문/다리의 실제 변화를 설명한다.
- 상자 충돌: 형태를 바꿀 때 땅 쪽으로 물러나도록 안내한다.
- 발판 충돌: 벽/경계와 지지 부족을 구분한다.
- 축에 수직 입력: 점선 방향 또는 빛 이동을 안내한다.
- 저장 불가: 현재 플레이는 가능하지만 닫으면 저장되지 않을 수 있다고 알린다.

완료 창은 기록 수치보다 방의 `meaning`을 보여준다. 어떤 해결 원리가 작동했는지 되짚는 용도다.

## 표시·접근성의 한계

작은 화면에서는 중복 문구/범례를 접어 게임판을 확보하고 전체 규칙은 도움말에 남긴다. 버튼은 대체로 44 CSS px 이상의 터치 영역을 사용한다. `aria-label`, 포커스 표시, 상태 알림, reduced-motion 처리를 제공하지만, 캔버스 퍼즐을 비시각 입력만으로 완주할 수 있다고 검증된 상태는 아니다.

JavaScript 차단 환경에서는 정적 미리보기와 실행 불가 안내를 보여준다. 이것은 게임 플레이나 오프라인 설치 기능이 아니다.
