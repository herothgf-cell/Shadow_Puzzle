# 12. 진행·저장·되돌리기

> 기준: V8.1.0 / main `5ea02af8c748bfc1207a06932154407bbf3a0232`. 이 문서는 현행 구현을 정리합니다. 기획 의도·제작 기준·후속 검토는 별도로 표시합니다.

## 저장의 범위

진행은 현재 기기·브라우저의 localStorage에만 저장한다. 게임 계정, 서버 저장, 기기간 동기화, 랭킹은 없다. GitHub Pages와 itch.io처럼 저장 원점이 다른 곳으로 기록이 자동 이전되지 않는다.

저장 키는 `shadow-morph-campaign40-v8`다. 제품 버전은 8.1.0이지만 현재 직렬화 객체의 `version`은 7이다. 저장 스키마 버전과 게임 버전을 혼동하지 않는다.

## 저장 데이터

| 항목 | 내용 |
|---|---|
| game.levelId / index | 안정적인 방 ID와 저장 당시 배열 번호. 복원은 ID로 찾음 |
| game.state | x/y/a, moves, won, latches, devices, 발판 ID별 길이 |
| game.lights | 광원 위치와 메타데이터 |
| activeShadow / activeLight | 선택한 그림자·광원 번호 |
| inputMode / target | 그림자/빛 모드, 상자/발판 대상 |
| completedIds | 완료한 방 ID 집합. 현재 목록에 없는 옛 ID도 보존 |
| fine | 정밀 모드 설정 |

되돌리기 history, 현재 드래그, 연출 큐는 저장하지 않는다. 새로고침 후 현재 상태는 이어지지만 새로고침 이전의 되돌리기 목록은 남지 않는다.

## 기록 시점

조작 종료, 대상/광원/모드 선택, 되돌리기, 다시, 방 진입, 정밀 설정, 클리어, 페이지 이탈 시 저장을 시도한다. 포인터 이동의 모든 프레임을 각각 저장하는 방식은 아니다. 저장 실패를 예외 처리하고 플레이는 계속 가능하게 한다.

## 복원과 검증

코어는 version 6 또는 7의 데이터를 받으며 유효한 levelId로 현재 방을 찾는다. 상자 좌표·비율·moves, 광원 수와 좌표, 발판 길이를 검증한다. 가동 광원은 허용 범위로 제한하고 고정광은 정의된 위치를 쓴다. 센서 래치 기록과 장치 안전 유지를 반영한 후 현재 상자가 실제 지형과 충돌하면 복원을 거절한다.

발판은 영구 벽·경계를 검사한다. 현재 닫힌 문이 이미 늘어난 발판 위에 존재할 수 있다는 V8.1 수정은 유지한다. 상자의 충돌 검사는 닫힌 문을 제외하지 않는다. 저장된 won은 실제 canWin을 충족할 때만 복원한다.

## 이전 버전과 재배치

읽기 순서는 현재 키 → `shadow-morph-v7-platforms` → `shadow-morph-v6-rebuild`다. 옛 번호형 완료 기록은 이전 19개 방의 고정 ID표로 변환한다. 이전 키를 삭제하거나 덮어쓰지 않는다.

재배치한 같은 ID는 새 번호에서 계속한다. 교체된 새 ID에는 옛 위치와 완료를 붙이지 않는다. 현재 캠페인에 없는 완료 ID를 보관하는 것과 새 방에 체크 표시하는 것은 다르다. 유효하지 않은 현재 상태는 기본 진입 상태로 남을 수 있으며, 복원 거절 전용 상세 오류 UI는 없다.

## 되돌리기 의미

최근 변경 100개까지 스냅샷을 저장한다. 상자·광원·발판·장치·선택 대상·입력 모드를 복구한다. 이동뿐 아니라 대상/모드 변경도 기록이 될 수 있다. 정밀 옵션은 UI 설정이라 이 스냅샷의 되돌리기 대상이 아니다.

moves는 변경된 트랜잭션 수다. 사용자 행동의 최적해 점수나 순수 이동 횟수로 정의돼 있지 않다. 향후 별점·최소 이동을 붙이려면 별도 지표 설계가 필요하며 현재 구현으로 표시하지 않는다.

## 진행 정책

모든 40방을 테스트용으로 고를 수 있다. 완료하지 않은 이전 방 때문에 다음 방이 잠기지 않는다. 다시/같은 방 재플레이는 completedIds를 초기화하지 않는다. 전체 데이터 삭제 버튼이나 계정 복구 기능은 없다.
