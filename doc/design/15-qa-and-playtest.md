# 15. 검증 기준·플레이테스트

> 기준: V8.1.0 / main `5ea02af8c748bfc1207a06932154407bbf3a0232`. 이 문서는 현행 구현을 정리합니다. 기획 의도·제작 기준·후속 검토는 별도로 표시합니다.

## 검증 목적을 나눈다

1. 규칙 정합성: 벽 통과, 지지, 저장, 장치 판정이 의도대로인가.
2. 해결 가능성: 현재 입력 규칙으로 출구까지 가는 경로가 있는가.
3. 이해/재미/난이도: 플레이어가 왜 막혔고 무엇을 발견했는가.

자동 해답 통과가 3번까지 증명하지 않는다. '테스트 통과'를 '재미 검증 완료'로 기록하지 않는다.

## 요소별 수용 기준

| 요소 | 확인할 행동 | 기대 결과 |
|---|---|---|
| 이동 | 한 번에 큰 드래그로 벽 너머 요청 | 중간 벽을 건너뛰지 않음 |
| 형태 | 최종 모양만 들어가는 좁은 곳에서 변형 | 중간 충돌에서 멈춤 |
| 그림자 | 상자만으로 ◇ 접촉 / 발판 그림자로 접촉 | 센서 켜지지 않음 |
| 그림자 | 비선택 그림자로 장치 접촉 | 정상 활성화 |
| 광원 | 빛만 이동 | 상자 위치 고정, 그림자/센서 갱신 |
| 축 | 수직 방향 입력 / 닫힌 벽 접촉 | 축 밖으로 밀리거나 미끄러지지 않음 |
| 유지판 | 그림자 끝만 겹치고 중심은 밖 | 비활성 |
| 래치 | 켰다가 벗어나기 / 되돌리기 | 켜짐 유지 / 이전 기록으로 복구 |
| 문 | 이미 열린 문 안에서 전원 해제 | 상자를 끼우지 않고, 나간 뒤 닫힘 |
| 발판 | 지나갈 길만 연결하되 폭 부족 | 상자 통과 불가 |
| 발판 | 올라선 상자의 바닥을 없애는 축소 | 안전 경계에서 정지 |
| 발판/문 | 늘어난 발판 위에 문이 닫힌 상태 저장 | 정상 상태는 복원, 상자 벽 관통은 거절 |
| 출구 | 그림자만 도착 / 상자 일부만 겹침 | 완료 아님 |
| 복원 | 같은 ID를 다른 번호로 재배치 | 해당 ID의 새 번호로 복원 |
| 복원 | 지형 교체한 다른 ID | 옛 위치·완료를 새 방에 붙이지 않음 |
| UI | 발판 2개+빛 2개 방 선택 | 두 종류 A/B 모두 조작 가능 |

## 기존 검사와 실행 범위

V8.1 릴리스 문서는 Node 검사 209개 및 3엔진 검증 절차를 기록한다. 이는 **해당 릴리스의 기록**이다. 이 문서 작성만으로 모든 브라우저/실기기 검사를 새로 완료했다는 뜻은 아니다.

`npm test`는 코어·레벨·저장/과거 회귀, `tests/hosting_browser.py`는 현재 캠페인의 실제 UI 입력과 HTTP/HTTPS, `npm run test:browser`는 보존한 이전 UI 회귀 흐름을 다룬다. 현행/보존 빌드를 혼동하지 않는다.

320×568, 360×640, 393×852, 844×390, 768×1024, 1365×768, 1920×1080의 배치, 회전, 키보드, 터치 직후 버튼, 저장/새로고침, 저장 차단, JavaScript 차단을 확인한다. Linux WebKit은 실제 iPhone Safari 사용성 검사와 동일하지 않다.

## 경로 검사와 우회 검사

전체 40방의 작성된 경로를 검증하고, 각 행동 뒤 저장 복원을 검사한다. 센서를 멀리 옮기거나 발판 재설정을 생략하는 대조 검사는 그 경로가 특정 요소에 의존함을 확인한다. 모든 가능한 우회가 없거나 유일해라는 증명은 아니다. 정상 대체 해법을 막기 위해 숨은 체크리스트를 넣지 않는다.

## 플레이테스트 기록 양식 — 후속 운영용

| 기록 항목 | 입력할 내용 |
|---|---|
| 빌드/방 | 버전·커밋·번호·ID |
| 조건 | 기기·화면 방향·입력 방식, 이전 플레이 경험 |
| 시간 | 첫 입력~완료, 힌트 전 정체 시간. 제한시간 아님 |
| 막힌 원인 | 규칙 이해 / 추론 / 조작 정확도 / 안내 가독성 |
| 발견 | 플레이어가 무엇을 깨달았다고 설명하는가 |
| 반복감 | 어느 이전 방과 어떤 이유로 같은 풀이처럼 느꼈는가 |
| 우회 | 예상보다 쉬운 해법과 필요한 조작 |
| 결과 | 순서 재배치 / 지형 재설계 / 입력 개선 / 안내 수정 / 유지 |

미숙련 플레이어와 기존 퍼즐을 익힌 플레이어의 결과를 구별한다. '11~12 뒤 13~14가 너무 쉽다' 같은 인접 역전뿐 아니라 후반의 독립된 쉬운 절차들을 길게 연결한 문제도 찾는다. 현재 수집·분석 서버나 자동 설문은 구현돼 있지 않다.
