# 16. 결정 이력·미확정 사항·후속 과제

> 기준: V8.1.0 / main `5ea02af8c748bfc1207a06932154407bbf3a0232`. 이 문서는 현행 구현을 정리합니다. 기획 의도·제작 기준·후속 검토는 별도로 표시합니다.

## 이미 반영된 결정

| 피드백/문제 | 현재 반영 | 문서 |
|---|---|---|
| 추상 규칙이 이해하기 어려움 | 그림자를 손잡이로 이동·변형하는 시각적 조작 | [그림자](04-shadow.md) |
| 목표에서 시작/재진입, 빠른 드래그 우회 | 초기 배치 검증, 연속 충돌, 상자 전체 출구 판정 | [플레이 흐름](02-core-loop-and-clear.md) |
| 숫자/SW 역할 불명확 | 실제 문/다리를 바꾸는 버튼·그림자 센서와 케이블 | [센서·장치](06-sensors-and-devices.md) |
| 그림자가 간접 이동 외에는 필요 없음 | 벽 너머 접촉, 광원으로 원격 작동, 비선택 그림자 유지 | [광원](05-lights-and-axes.md) |

| 모바일 빈 화면/조작 불편 | 실행 불가 안내, 패드·프리셋·정밀·화면별 배치 | [UI](08-controls-and-ui.md) |
| 발판 작업면과 문 상태 저장 거절 | 현재 상자 충돌을 지키면서 정상 발판 상태 복원 | [저장](12-save-and-progression.md) |

위 목록은 피드백에 대한 구현 대응이며 문제의 체감상 완전 해결을 선언하지 않는다.

## 문서 간 우선순위

현행 코드와 레벨 데이터 → V8.1 릴리스/재편 문서 → 과거 V8/V7 기획 순서로 현재 동작을 확인한다. 다만 코드가 사용자 기획 의도와 다르면 그 차이를 버그/검토 대상으로 기록하지, 사용자가 그런 규칙을 의도했다고 바꾸어 쓰지 않는다.

이 대화에서 확정한 디자인 철학은 플랫폼을 한정하지 않고, 장래 신규 기믹 가능성을 열어둔다. V8.1에서 신규 기믹을 추가하지 않았다는 범위와 장기 목표를 분리한다.

## 남은 과제 — 미구현/미확정

| 항목 | 현재 상태 | 다음 판단 기준 |
|---|---|---|
| 40방 실제 난이도 곡선 | 설계자의 상대 순서, 사용자 실측 부족 | 힌트 전 해결/정체 이유와 반복감을 수집 |
| 실기기 입력 | 브라우저 엔진 검사와 별개 | 실제 iPhone/Android의 드래그·회전·가독성 |
| 단계별 힌트 | 방별 단일 hint만 구현 | 해법을 바로 노출하지 않는 단계화가 필요한지 |
| 소리·진동 | 현행 런타임에 없음 | 의미 전달 기여, 음소거 및 자산 사용 조건 |
| 커버/아트 방향 | 홍보 시안과 실제 2D 화면 구분 | 플레이를 오해시키지 않는 최종 표현 |
| 별점·최소 조작·랭킹 | 없음 | 모드 변경도 moves인 현재 지표 재정의 필요 |
| 저장 내보내기·기기간 동기화 | 없음 | 필요성·개인정보·운영 범위 검토 |
| 신규 기믹 | 이번 캠페인에 추가하지 않음 | 기존 규칙의 재미·이해를 해치지 않는지 별도 승인 |
| 상업 출시/플랫폼/서사 | 확정된 상세 자료 없음 | 별도 기획 결정 필요 |

## 과거 아이디어 — 현행 기능이 아님

추/도르래, 기계 정지, 발판 이동·회전, 그림자 합체·분할 등의 아이디어는 대화에서 후보로 언급됐으나 현재 코드에 없다. '개발 예정 확정'으로 일정이나 스테이지에 넣지 않는다. 향후 선택할 수는 있지만 별도 규칙·학습·검증 설계가 필요하다.

## 검토가 필요한 표현과 구현 차이

- 여러 문이 닫히는 문제에서도 기존 끼임 방지로 통과 중인 상자는 보호된다. '그늘을 잠깐이라도 놓으면 실패'라고 설명하면 실제와 다르다.
- 연결 완료 발판 안내는 전 구간 통과를 보증하지 않는다. 닫힌 문·돌벽은 별도다.
- 현재 자동 목표 안내는 첫 닫힌 장치를 소개한다. 최적해나 강제 행동 순서로 오해되는지 확인한다.
- 방 선택은 항상 열려 있다. 튜토리얼 이전에 어려운 방으로 가는 사용자를 별도 차단하지 않는다.
- 제품 버전 8.1과 저장 스키마 7, 과거 파일명의 V7/V8은 서로 다른 개념이다.

## 다음 작업에 전달할 원칙

먼저 바꾸려는 기획 의도와 현행 판정 차이를 명시하고, 요소 문서·레벨·해답·저장 ID·UI 문구를 함께 검토한다. 기존 코드가 허용하는 정상 대체 해법을 임의로 '편법'이라고 막지 않는다. 신규 규칙은 현재 구현 설명에 섞지 않고 결정 후 반영한다.
