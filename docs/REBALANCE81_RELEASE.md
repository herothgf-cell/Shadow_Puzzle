# V8.1.0 — 난이도 우선 재배치와 후반 재설계

## 승인 범위 및 실제 변경

원문: [사용자 승인 재배치 제안](Shadow_Puzzle_Difficulty_Rebalance_Proposal.md).
40개 방, 신규 기믹 0개를 유지합니다. 기존 28개 방은 **지형 ID 및 실제 판정 데이터를 보존**해 재배치했고, 나머지 12개는 새 ID의 지형과 입력 해답으로 교체했습니다. 원래 40개 방과 해답은 `tests/v8-levels.cjs`, `tests/v8-solutions.json`으로 회귀 검사합니다.

‘12번까지 모든 기믹 소개 완료’ 기준을 폐기했습니다. 기존 13번은 5번, 14번은 10번으로 앞당겼습니다. 두 광원 첫 등장은 23번(기존 11), 유지형 그늘은 29번(기존 12)부터입니다. 1~8 기본 조작, 9~16 단일 장치와 길, 17~22 빛/작업 위치, 23~28 두 축, 29~34 그늘 유지, 35~40 설정 재사용으로 배치했습니다. 이는 설계자의 상대 난도 추정이며, 모든 플레이어에게 매 방 단조롭게 어려워진다는 측정 결과가 아닙니다.

## 후반의 다른 판단

- 25: 목표와 빛의 교점을 한 번 찾는 문제가 아니라, 기둥을 피해 여러 축을 갈아탈 자리를 마련합니다.
- 26: 좁은 틈을 건너는 형태와 다음에 사용할 대각축을 함께 준비합니다.
- 27: 첫 그림자 장치에 닿기 위해 출구에서 먼저 멀어져야 하며, 다음 문은 다른 작업 위치를 요구합니다.
- 28: 빛 A의 이동 범위를 넘어서는 귀환 방향은 고정된 B로 해결합니다.
- 30·34: 한 번 켜면 끝나는 버튼 방문 대신, 다른 문으로 넘어가기 전에 유지할 그늘 배치를 다시 정합니다.
- 35: 발판을 작업대로 쓰는 것에 그치지 않고, 그 작업 위치에서 유지형 문과 다음 빛축을 함께 마련합니다.
- 36: 두 수로의 길이/지지 폭과 그늘 역할이 다릅니다. 마지막 착지 후 넓힐 공간도 고려합니다.
- 37: 처음부터 모든 다리를 길게 펼 수 없습니다. 짧은 첫 연결로 그늘판이 눌리는 위치에 들어가 다음 확장 공간을 열고, 섬에서 광원 역할을 넘깁니다.
- 38: 갈 때의 그늘 배치가 귀환 문에는 맞지 않습니다. 새 다리가 생겨도 빛 B의 자리를 바꿔 돌아올 그늘을 준비해야 합니다.
- 39: 내려가는 문과 옆으로 나가는 문이 서로 다른 그늘을 요구합니다. 두 광원을 서로 다른 역할로 다시 씁니다.
- 40: 건넌 A를 작업면으로 바꾼 후에도 끝이 아닙니다. 두 문 사이에서 B 발판을 마저 펼치려면 두 그늘의 배치를 바꾸고, 다시 출구용 축으로 전환해야 합니다.

이전 26/31/35의 단순 작업대 변형 반복, 이전 28/37의 동일한 교점 발상 반복을 그대로 후반에 줄세우지 않았습니다. 첫 작업대 문제(새22)와 새35·40은 같은 기술을 쓰지만 문 유지/발판 확장 선행 관계가 추가된 별도 문제입니다. 시각적·체감 반복감은 여전히 플레이테스트 대상입니다.

## 판정 변경이 아닌 저장 버그 수정

실제 실행 중 이미 늘려진 발판 위로 유지형 문이 닫힐 수 있는데, 이전 저장 복원은 이를 불가능한 상태로 취급했습니다. 새 복원은 발판의 **영구 돌벽/경계** 검사를 유지하고, 상자는 실제 닫힌 문을 포함해 충돌 검사합니다. 문을 임의로 열거나 상자를 통과시키지 않습니다. 이동·변형·지지·센서·문 끼임 방지의 런타임 판정은 변경하지 않았습니다.

새 센서 종류, 그림자 독립 이동, 다리 자유 이동/회전, 타이머, 추가 횟수 제한은 없습니다. 두 그림자는 여전히 같은 상자를 따라 함께 움직입니다.

## 저장과 화면

저장 키 `shadow-morph-campaign40-v8` 및 ID 기반 복원을 유지합니다. 재배치한 28개 방은 기존 진행을 새 번호로 이어받습니다. 교체한 12개 방에는 옛 위치/완료를 붙이지 않고, 옛 완료 ID는 보존합니다. V6/V7 원본 키는 읽기만 합니다.
`23+` 버튼은 두 광원 구간으로 갑니다. `?stage=11`, `?stage=23`, `?stage=40` 같은 번호 링크도 유지합니다. 도움말의 광원/발판 소개 번호와 스테이지 선택 분류를 새 배열에 맞췄습니다. 해답의 정확한 행동 순서는 기존 힌트 뒤에 남기며 후반의 상시 설명은 목표와 고민할 관계를 중심으로 합니다.

## 검증과 한계

- Node 전체 209개 검사: 기존 V7/V8 회귀 + 새40 입력 경로 + ID 이전 + 저장 버그 + 구조/센서 무력화 대조.
- 전체 40방을 실제 엔진 입력으로 클리어하고 매 행동 후 저장 복원까지 확인합니다.
- 새 방의 각 센서를 멀리 옮긴 경우 작성된 해답이 막히는지 확인합니다.
- 35·37·40은 같은 경로에서 발판의 두 번째 이후 설정 변경을 생략하면 완료되지 않는 대조 검사를 둡니다. 이는 해당 경로의 의존성 검사이지 모든 우회 해법이 없다는 증명은 아닙니다.
- 36/37/38/39가 모두 ‘발판 재설정 필수’인 것은 아닙니다. 방마다 축·광원 역할·유지형 조건 등 서로 다른 판단을 이용합니다.
- 닫히는 문이 상자를 끼우지 않는 안전장치와 다른 정상 해법을 인정하는 원칙을 유지합니다.
- 브라우저 검사는 320×568~1920×1080, 모바일 세로·가로, 40개 실제 입력, PC 키보드, 터치, 저장/새로고침을 확인합니다. GitHub Actions의 3엔진 전체 검사 후만 Pages에 배포합니다.
- 로컬 컨테이너에서 네트워크 탐색이 금지돼 로컬 Chromium은 동일 HTML의 메모리 모드로 검사합니다. 실제 HTTP/HTTPS 검증은 Actions에서 수행하며 서로 구분합니다.
- 자체 코드 검토와 자동 테스트입니다. 독립 검토자·실제 iPhone/Galaxy·체감 난도/해결 시간 검증으로 표현하지 않습니다.
