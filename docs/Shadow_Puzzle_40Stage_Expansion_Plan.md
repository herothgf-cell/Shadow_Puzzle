## 1. 결정 요약

- 신규 기믹은 0개. 현재 엔진의 지형·장치·빛·발판 데이터 조합만 사용한다.
- 1~12: 주요 기믹 학습 완료.
- 13~16: 기존 두 규칙을 엮는 연습.
- 17부터: 출구에서 역산하고, 먼저 무엇을 준비해야 하는지 판단하는 본격 퍼즐.
- 25부터: 안전한 변형 장소, 상태 유지, 장치 선행 관계가 얽히는 고난도.
- 33~40: 적은 요소의 발상 문제와 종합 문제를 섞는 최종 도전.
- 스테이지 번호를 억지로 늘리지 않는다. 기존 19개의 학습용과 종합형을 재배치·수정하고 새 지형을 더해 40개를 구성한다.
- 지형의 실루엣뿐 아니라 '왜 그 행동을 해야 하는가'가 달라져야 별도 스테이지로 인정한다.

## 2. 사용 가능한 기존 규칙과 금지선

### 사용
1. 상자 그림자를 움직여 상자를 같은 방향으로 이동. 현실 벽은 상자를 막고 그림자는 통과.
2. 상자 면적을 유지하는 가로/세로 형태 변경.
3. 상자용 바닥 버튼, 상자 그림자용 점형 장치, 유지형 그늘판.
4. 한 번 작동하면 유지되는 latch와 접촉 중에만 작동하는 유지형 센서.
5. 센서와 연결된 실제 문 및 자동 다리.
6. 고정/이동 광원, 상자 위치를 유지한 광원 이동, 광원-상자 축 이동, 두 그림자 선택.
7. 고정 중심·고정 방향 발판의 길이 변경. 발판은 길어질수록 폭이 좁아진다.
8. 기존 되돌리기, 정밀 모드, 힌트, 선택 UI.

### 추가하지 않음
발판 자유 이동/회전, 추와 도르래, 기계 정지, 새로운 이동 재질, 적, 타이머, 이동 횟수 제한, 그림자 복제/분리/합체, 색 혼합, 중력, 공유 에너지/길이 자원, 새 논리 회로.

### 반드시 지킬 실제 구현 의미
- 두 그림자는 같은 상자를 따라 함께 움직인다. A를 독립적으로 고정해 둔 채 B만 움직이는 규칙은 없다.
- 직사각형 유지형 그늘판은 그림자 중심으로 판정한다. 전체 그림자가 완전히 덮어야 한다거나 폭이 넓으면 더 강하게 누른다는 규칙은 없다.
- 점형 ◇ 장치는 상자 그림자의 실제 타원 범위로 판정하므로 형태 변경을 이용한 접근은 기존 규칙의 응용이다.
- 발판 그림자는 조절 손잡이이다. 현재 장치를 작동시키는 그림자는 상자 그림자이다.
- 문/다리 하나는 sensorId 하나로 구동한다. 두 조건을 요구하려면 독립된 문 두 개를 배치하지, 새 AND/OR 판정을 만들지 않는다.
- 광원과 발판은 원격 조작 가능하다. '그 장소에 가야만 선택할 수 있다'는 가짜 선행 조건을 쓰지 않는다.
- 광원은 벽에 빛이 가려지는 시뮬레이션이 아니다. 벽으로 빛을 차단하는 퍼즐을 설계하지 않는다.
- 발판끼리는 길이나 면적 자원을 주고받지 않는다. 각각의 면적 보존만 적용한다.
- 문 끼임 방지와 발판 지지 안전장치를 유지한다. 안전장치 제거·빠른 입력·손가락 두 개 동시 조작을 해법으로 요구하지 않는다.
- 클리어는 실제 상자 전체가 출구에 들어가는 조건이다. 모든 장치를 방문했는지 따로 검사하지 않는다.
- 자유 이동 방과 빛축 이동 방의 기존 차이는 시작 설명, 기존 tag, 점선으로 먼저 알린다. 후반에 갑자기 설명 없는 입력 반전을 넣지 않는다.

## 3. 난이도 기준

여기서 '판단'은 드래그 횟수가 아니라 형태/빛축/발판 설정/이동 순서/유지 조건 중 의미 있는 선택이다.
아래 시간은 게임 제한시간이 아니며, 힌트 없는 첫 플레이의 관찰 목표이다. 아직 측정한 값이 아니다.

| 구간 | 핵심 판단의 목표 | 첫 플레이 관찰 목표 | 안내 |
|---|---|---|---|
| 1~12 | 한 관계를 익히고 바로 확인 | 방당 20~90초 | 조작과 결과를 직접 알려준다 |
| 13~16 | 두 관계를 순서대로 엮음 | 1~3분 | 조작 대신 목표 관계를 알려준다 |
| 17~24 | 2~3개의 선행 관계/조건 | 2~5분 | 무엇을 준비할지 스스로 찾는다 |
| 25~32 | 3~4개의 연동된 판단 | 3~7분 | 막혔을 때 핵심 질문을 힌트로 준다 |
| 33~40 | 4~5개의 판단 또는 소수 요소의 깊은 발상 | 4~10분 | 새 규칙 없이 조합을 완성한다 |

판 수가 올라갈수록 계속 맵과 장치 수를 키우지 않는다. 28·37 같은 작은 발상 방을 끼워 조작 피로를 줄인다.

## 5. 먼저 검증할 대표 퍼즐

### 17 — 출구 조건에서 역산
출구 쪽 가는 회랑은 세로형 상자를 요구한다. 수로를 가로지르는 발판을 끝까지 늘리면 세로형 상자의 높이를 받치기 어려워진다.
두 강둑을 연결할 만큼은 길면서 세로형을 받칠 만큼은 넓은 설정을 먼저 찾고 건너게 한다.
틀렸을 때는 되돌아오거나 되돌리기로 수정할 수 있다. 출구 회랑에서 변형이 실제로 가능한 우회 해법이 있다면 막무가내로 실패 처리하지 않고 난이도 목표와 비교해 검토한다.
검증: 출구 접근 형태, 발판의 유효 길이 구간, 장거리 확장의 폭 손실, 도착지 변형 여유를 모두 좌표로 증명.

### 26 — 발판을 작업면으로 쓰기
서로 직각인 고정 발판 A/B가 물 위 중앙에서 만난다. 돌로 된 넓은 섬은 없다.
가로로 긴 A를 납작한 상자로 건넌 뒤 중앙에서 A를 짧고 넓게 바꿔 작업면을 확보한다.
그 위에서 세로형으로 바꿔 세로 발판 B로 나간다.
두 발판을 처음부터 끝까지 길게 두면 중앙의 지지가 형태 변환 중간을 받치지 못하도록 설계한다.
A/B는 이동하거나 회전하지 않는다. 기존 길이-폭 관계와 실제 바닥 지지 판정만 사용한다.
검증: 모양 변환의 모든 중간 형태가 지지되는 해법, 길게 고정한 두 발판만으로 변형하는 우회 가능성, 중앙 도착 오차 여유, 안전한 발판 축소.

### 33 — 두 독립된 문
문 A와 문 B에 각각 자기 그늘판을 연결한다. 장치 하나에 여러 센서 판정을 추가하지 않는다.
두 그림자의 중심 이동 범위와 현재 이동축을 이용해 두 문을 통과 가능한 위치 관계를 만든다.
A/B 그림자가 각각 고정되어 있는 것으로 설명하지 않으며, 정상적인 다른 그림자/경로 조합도 허용한다.
검증: 문 사이 공간과 끼임 방지 로직을 포함한 실제 진행, 단일 그림자 대체 해법, 센서 유지 범위의 모바일 조작 여유.

## 6. 반복과 억지 난이도를 막는 제작 규칙

1. 회전·좌우 반전·장치 위치만 이동한 맵을 새 스테이지로 세지 않는다.
2. 입출구·변형 장소·장치 관계·필요한 상태 전환이 같으면 지형 그림이 달라도 중복 후보로 본다.
3. 각 방에는 제작자가 한 문장으로 설명할 수 있는 고유한 '아하'가 있어야 한다.
4. 긴 이동, 좁은 판정 여유, 잦은 선택 전환만으로 시간을 늘리지 않는다.
5. 모든 버튼/장치는 문·다리 등 실제 변화에 연결한다. 숫자 방문 순서 체크는 복구하지 않는다.
6. 필수라고 명명한 기믹 없이도 쉽게 클리어하면 설계를 재검토한다. 반대로 정상적인 기하·상태 규칙으로 푼 창의적인 해법은 허용한다.
7. 잘못 준비했으면 결과를 보고 되돌릴 수 있어야 한다. 정답을 누르지 않았다는 보이지 않는 이유로 실패시키지 않는다.
8. 마지막 방은 대형 미로가 아니라 한 화면의 세 작업 구역으로 구성한다.
9. 권장 복잡도 상한은 상자 1개, 광원 2개, 조절 발판 2개, 실제 작동 장치 약 3개이다. 이는 새 게임 제한 규칙이 아니라 제작 가이드이다.
10. 형태·발판 설정의 해답은 넓은 유효 범위를 갖게 한다. 픽셀 단위 슬라이더 수치 맞추기를 핵심으로 삼지 않는다.

## 7. 개발 분류와 순서

### A. 대표 고난도 3개부터
17·26·33의 회색 박스 맵을 기존 엔진으로 먼저 구성하고 실제 해결 경로를 재생한다.
아이디어가 성립하지 않으면 지형·기존 수치·배치를 고친다. 새 판정 규칙을 넣어 억지로 성립시키지 않는다.

### B. 초반 압축과 캠페인 재배치
기존 19개를 보관하고, 학습용은 1~12로 앞당긴다. 기존 발판 15~19의 학습은 7~8부터 접하게 한다.
기존 복합 문제를 13 이후 적절한 자리에 재배치·개선한다. 맵 19개를 모두 버리고 처음부터 다시 만들 필요는 없다.

### C. 중반 → 후반 순서로 완성
13~24의 선행 관계/유지 조건 학습을 마친 뒤 25~40의 고난도 조합을 제작한다.
각 방마다 데이터, 한 문장 의도, 정상 해결 경로, 의도한 기믹을 건너뛰는 시도, 힌트를 함께 검토한다.

### D. 필요한 기술 보완만
- src/levels.js: 레벨 데이터와 chapter/tag/tip/hint, 안정적인 levelId를 기준으로 정리.
- src/ui.js: 발판이 있는 방에서도 광원 A/B 선택을 함께 볼 수 있게 기존 선택 UI 배치를 보완. 현재 modeRow는 발판이 있으면 숨겨지므로 복합 레벨에 앞서 점검.
- src/core.js / 저장 처리: 현재 restore는 index와 levelId가 일치해야 하므로 재배치 시 ID 기반 매핑을 먼저 해야 함.
- 같은 내용의 방은 ID로 완료 기록과 진행을 이전. 실제 지형이 바뀐 방은 새 revision/ID로 구분하고 과거 완료 이력은 별도 보존. 새 방에 과거 클리어를 잘못 붙이지 않음.
- 수동 테스트용 전체 스테이지 선택은 유지. 17번 이후를 바로 검증할 수 있게 기존 바로가기 숫자/라벨을 새 구성과 일치시킴.
- 목표 표시: 현재 objective()가 첫 미작동 장치를 고르므로, 독립된 두 작업의 순서가 자유인 방을 '이 버튼부터 필수'로 잘못 안내하지 않게 문구 처리 점검.
- 테스트와 빌드의 고정 19/15+ 표기, version.json의 stages, 마지막 방 완료 메시지와 캠페인 해답 수를 40에 맞춤.
- 신규 퍼즐 규칙을 추가하는 엔진 변경은 하지 않음. 기존 UI 조합/저장 호환/데이터 검증만 보완.

### E. 완료 기준 후 배포
모든 방의 초기 유효성, 실제 입력 클리어, 충돌/지지, 저장/되돌리기, 모바일 화면 및 기존 CI를 통과시킨 뒤 main에 반영하고 동일한 Pages 주소로 배포한다.
이 문서는 배포를 수행했다는 기록이 아니다.

## 8. 검증 기준

- 40개 모두 시작 시 출구와 겹치거나 이미 클리어되지 않음.
- 각 방의 실제 입력을 이용하는 정상 해결 경로 최소 1개. 39번은 순서가 다른 정상 해법 2개.
- 닫힌 문 관통, 빠른 드래그 벽 통과, 지지 없는 물 위 이동, 형태 변경 중간 충돌, 발판 축소로 지지 상실을 차단.
- 센서/문/다리/빛/발판/선택 상태가 되돌리기·저장·새로고침에서 일치.
- 그늘판은 중심, 점형 장치는 타원 접촉이라는 실제 기준과 화면 안내가 일치.
- 시작 상태의 모든 장치를 먼 곳에서 조작해 정답 순서를 건너뛸 수 있는지 확인. 합법적 대안과 오류를 구분.
- '발판 전부 최대', '형태 한 가지 고정', '빛을 움직이지 않기', '센서 무시하고 출구 접근' 등을 방의 목적에 맞춰 대조 검사.
- 회전·반전 포함 지형 중복 검사와 제작자/플레이어의 해결 과정 중복 검토를 함께 수행.
- PC 마우스/키보드와 모바일 터치로 동일 경로를 완수. 기존 Chromium/WebKit/Firefox 검사 유지.
- 자동화 성공과 사람의 체감 난이도는 구분. 첫 플레이 관찰은 헷갈린 규칙/의미 있는 고민/입력 실수/동선 지루함을 따로 기록.
- 실기기 확인에서는 화면 전환, 선택 UI, 그늘 유지 허용 오차, 슬라이더 유효 범위를 확인.
- 17·26·33·40에서 자동 해답 존재만으로 난이도 달성이라고 선언하지 않음.
